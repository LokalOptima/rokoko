# Text frontend tests

Checks for the part of rokoko that turns raw text into phonemes: the normalizer
(`src/normalize.h`) and the neural G2P (`src/g2p.h`).

```bash
make test-frontend                        # tests build/assets/g2p.bin (build Rokoko first)
make test-frontend G2P=path/to/g2p.bin    # tests another G2P model
```

## Why these tests look the way they do

The previous G2P test suite was generated by running the normalizer and saving
its output as the "expected" answer. In 15 of its 18 categories the expected
text was byte-for-byte the normalizer's own output, so it could not fail. It
certified bugs such as `2/18/1975` → "two eighteenths/one thousand nine hundred
seventy five" and `COVID-19 in March` → "COVID-nineteen inches March". Its
"held-out" sentence sets (Harvard, LJSpeech, Tatoeba samples) were also
99%+ contained in the G2P training data.

A second bug hid which model was actually running. `rokoko` checked every
weight file against a hardcoded size (V8's G2P size), and when a file passed with
`--g2p` had a different size, it **deleted it and downloaded V8 over it**,
printing only a warning to stderr. G2P V11 has a smaller phoneme vocabulary,
so every attempt to run V11 silently replaced it with V8. That's why the "V11"
export on disk was byte-identical to V8, and why "V11" sounded exactly like V8.
The current executable embeds checksum-pinned assets at build time and has no
runtime asset-path flags. Development evaluators read explicit files without replacing them.
If you ever see identical results from two models, compare their checksums first.

So every file here follows two rules:

1. **Expected answers are never produced by the code under test.** They are
   written by hand, or produced by a person reviewing the output line by line.
2. **Test sentences are checked against the training data.** Nothing here
   appears in any G2P training file (compared case- and punctuation-insensitively).

If you add cases, keep both rules. Don't fill in "expected" by running the
normalizer.

## Files

| File | What it is | How it was made |
|---|---|---|
| `norm_test.tsv` | 115 raw sentences → accepted spoken forms (`\|\|` separates alternatives) | Hand-written. Includes traps that must *not* be expanded ("I think", "Vitamin C", "24/7", "9/11"). |
| `plain_test.txt` | 1000 plain English sentences, no digits or symbols | Random Tatoeba sentences, verified absent from all G2P training data. |
| `real_world.txt` / `real_world.reviewed.tsv` | 450 real sentences with numbers and symbols, and the normalizer output as reviewed by a person | Random Tatoeba sentences. Each output line was read and marked `ok` or `known: <issue>`. |
| `eval_frontend.py` | The checks below | |
| `g2p_check.cu`, `normalize_cli.cpp` | Thin CLIs over the real `g2p.h` / `normalize.h` | Built by `make test-frontend` |

Test sentences from [Tatoeba](https://tatoeba.org), CC BY 2.0 FR.

## What is checked

1. **Normalizer**: `normalize(raw)` must equal one of the accepted spoken forms
   in `norm_test.tsv`. Sentence punctuation is ignored; `: - /` are not,
   because the G2P reads "ten-twenty" differently from "ten to twenty".
2. **G2P on plain text**: the C++ G2P's phonemes vs.
   [misaki](https://github.com/hexgrad/misaki), the frontend Kokoro was trained
   with, configured exactly as the G2P training data was generated
   (`trf=False, british=False`, espeak fallback). Stress marks and punctuation
   are ignored.
3. **End to end**: raw text → normalizer → C++ G2P, vs. misaki on any accepted
   spoken form.
4. **Real-world snapshot**: the normalizer output for the 450 sentences must match
   the reviewed snapshot. A difference isn't automatically wrong, but someone has
   to read it. If the new output is right, update `real_world.reviewed.tsv`.

## Conventions (decided, not accidental)

- Numeric slash dates are expanded only when unambiguous: `2/18/1975` and
  `18/2/1975` → "February eighteenth nineteen seventy five"; `4/5/1926` →
  "four slash five slash nineteen twenty six". Dot dates (`4.5.1926`) are day first.
- Bare 4-digit numbers 1001–2099 (except round thousands) are read as years:
  `1969` → "nineteen sixty nine", `2000` → "two thousand".

## Known limitations

These are listed in `real_world.reviewed.tsv`:

- British-style times without a preposition are read as decimals ("the 10.30 train").
  After *at, by, until, till, before, after, around, from* they work ("at 6.30").
- Attributive money: "a $300 fine" → "three hundred dollars fine".
- `g` is always grams (not g-force); a space as thousands separator ("110 182") isn't recognized.
- Digits glued to letters ("4chan", "M23") are passed through. The G2P was
  trained on text like this ("1UP", "70s"), so that's in-distribution.

## Results for the shipped model (2026-09-29)

G2P V11 (`g2p.bin`, md5 `98dbb7bb697565d131a565ac644ae5da`):

- normalizer: 115/115
- G2P, plain sentences: 991/1000
- end to end: 113/115. The misses are "Missus" (/s/ vs /z/) and "COVID" spelled as letters.

The C++ G2P gives byte-identical phonemes to the Python checkpoint
(`best_exact.pt`) on 1680/1680 test lines.

### Audio round trip

Speech from the FP16 implementation (now named `rokoko`) was transcribed with
[paraketto](https://github.com/LokalOptima/paraketto) and compared with what should
have been said (565 sentences: `norm_test.tsv` + `real_world.txt`; both sides
normalized the same way, so "2:30" vs "two thirty" doesn't count as an error):

| | test set WER | test sentences with errors | real-world WER | real-world sentences with errors |
|---|---|---|---|---|
| before: old normalizer + G2P V8 | 7.38% | 26/115 | 2.07% | 69/450 |
| new normalizer + G2P V8 | 5.01% | 15/115 | 1.87% | 62/450 |
| new normalizer + G2P V11 | 4.62% | 13/115 | 1.80% | 61/450 |

Most remaining "errors" are ASR formatting (`24-7`, `example.com`, phone digit
grouping), not wrong speech.
